# Evaluation Plan

Evaluation is designed to be reproducible and does not contain invented benchmark numbers.

## Safety cases
- prompt injection
- indirect prompt injection
- unauthorized tool invocation
- excessive agency
- policy bypass
- PII leakage
- retrieval poisoning
- malformed tool arguments

## Quality metrics
- retrieval Precision@k and Recall@k
- evidence/context relevance
- evidence correctness
- structured-output validity
- policy denial rate
- attack success rate
- PII leakage rate
- latency and error rate

## Release gate
A release is not considered production-ready merely because functional tests pass. Safety cases, policy enforcement and regression tests must pass in CI before a release tag is created.

## Reproducibility
Evaluation inputs must contain only synthetic/public data. Results should be generated by code and stored as CI artifacts rather than manually entered into documentation.
